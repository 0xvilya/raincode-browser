# Участие в разработке

Начните с [README](README.md), [ARCHITECTURE](ARCHITECTURE.md), [SECURITY](SECURITY.md) и [THREAT_MODEL](THREAT_MODEL.md). Команды установки, запуска и упаковки находятся в [BUILDING](BUILDING.md).

## Рабочий процесс

1. Проверьте `git status` и сохраните чужие изменения. Для отдельной задачи используйте отдельную ветку.
2. Установите зависимости через `pnpm install --frozen-lockfile`; не меняйте lockfile без причины. Используйте версию pnpm из `packageManager`.
3. Меняйте минимальный необходимый объем кода. Пользовательские строки добавляйте в словари ru/en.
4. Выполните lint, typecheck, unit/integration и соответствующие e2e-проверки. Для браузерного изменения запустите настоящий Electron: Vite preview не подтверждает загрузку сайтов.
5. Опишите наблюдаемое поведение, тесты и оставшиеся ограничения. Обновите ROADMAP, если функция действительно завершена.

## Правила безопасности

- Не выключать sandbox, Site Isolation, TLS, contextIsolation, webSecurity или permission prompts.
- Не подключать Node.js и API оболочки к внешним страницам.
- Любую новую IPC-команду добавлять в shared allowlist, runtime schema и sender validation.
- Не добавлять универсальные команды исполнения JS/shell/файловых путей из renderer.
- Не отправлять историю, cookies, секреты, полный URL с query или proxy credentials в логи/аналитику.
- Не добавлять сетевой запрос при запуске или установку расширения без явного решения пользователя.
- Импортируемые настройки и workspace считаются недоверенными данными; никаких команд или автоматической загрузки кода.
- Не объявлять новый режим приватным или анонимным по одному тесту IP-адреса.

## Тестовые данные

Используйте локальные HTTP/HTTPS/Proxy fixtures и временные userData-каталоги. Не передавайте тесту рабочий профиль пользователя. Не тестируйте опасные загрузки на настоящих исполняемых файлах; достаточно инертных данных с тестовым именем. Для Tor пригодны собственная тестовая сеть и контролируемый onion service, а не случайные адреса.

Скриншоты и сетевые traces не должны содержать рабочие токены, личную историю и учетные записи. Запрещено подменять успешным статусом непройденную проверку: skipped и not tested должны оставаться видимыми.

## Pull request

Укажите проблему, поведение после изменения и выполненные проверки. Для изменений сети и IPC добавьте короткое описание границ доверия. Для новой зависимости приведите назначение, официальную документацию, license и влияние на сборку. Для UI добавьте скриншот реального окна и проверку keyboard/reduced-motion.

У проекта пока нет SLA review. Уязвимости сообщайте по процедуре в SECURITY, а не публичным issue с секретами.
