# Приватность RainCode Browser 0.5.5

0.5.5 Page Context: сбор только после явного действия и native read permission, отдельно для каждого видимого источника. Scope включает profile/tab/origin/native document ID. Точный ограниченный preview хранится только в памяти и передаётся один раз после подтверждения; для облака отдельное native согласие с фактическим origin провайдера и списком источников. Данные оборачиваются как недоверенный текст, инструментов выполнения команд у модели нет. Формы, скрипты, скрытые/editable элементы, iframe, cookies/storage и URL paths/query/fragments исключаются. Редактор маскирует очевидные токены/ключи/email, но не умеет гарантированно найти все секреты; предпросмотр нужно проверить целиком. Тикеты истекают через60s; navigation/close/crash/profile change/Stop/lock/revoke прекращают доступ. Никаких скриншотов или фонового Live-сбора. Историческое описание0.5.4 ниже относится к предыдущей версии.

0.5.4: ИИ доступен явно через боковую кнопку. Внешнему сервису передаются только введённые пользователем сообщения после Send; для совместимого облачного API требуется отдельное согласие на каждый запрос. Встроенный тест облачной модели требует подтверждения и отправляет только фиксированную тестовую фразу. Страницы/DOM/cookies/console/снимки/Live/Compare не собираются этой версией. Сохранение конфигурации и открытие панели не делают сетевых запросов. Ollama вызывается только по loopback после явного действия; отдельные модели Ollama могут сами обращаться в облако. Чат хранится только в памяти панели, ограничен по объёму; ключи только в OS-encrypted SecretStore, конфигурация без ключа в SQLite. ИИ пока разрешён в Direct-профилях; не переносит запрос в Direct из Tor/Proxy.

Standard/Strict/Maximum управляют локальными known-host tracker rules, сетевыми Cookie/Set-Cookie и JavaScript. Strict фильтрует cookies у HTTP(S)/WS(S) запросов между разными origin и у запросов с неизвестным источником. Same-origin cookies остаются разрешены; JavaScript доступ к существующим third-party cookie/storage не считается полностью заблокированным. Maximum по умолчанию отключает JavaScript. Точные origin-исключения могут ослаблять выбранную политику; настройки глобальные для браузера, разрешения сайтов остаются привязаны к профилю. Это не унификация fingerprint с Tor Browser.

Оболочка UI разрешает только встроенные ресурсы (в dev — явно выбранный Vite origin); внешние HTTP/WS отменяются. WebContents имеют spellcheck:false, чтобы не загружать словари с CDN. Это ограничение документированного [Electron spellchecker](https://www.electronjs.org/docs/latest/tutorial/spellchecker/). Запрет всех сервисов Google в Chromium/ОС не сертифицирован: сайты могут намеренно загружать свои ресурсы. `node scripts/audit-background-network.mjs` запускает собственный чистый профиль и собирает только NetLog metadata при старте+15секундах ожидания, без пользовательских страниц; это [Chromium NetLog](https://www.electronjs.org/docs/latest/api/net-log/), а не полный OS packet capture. Результат хранится локально в artifacts/background-network-0.5.4.json.

0.5.0: tracker ledger хранится только в памяти, до200 групп, с настоящими event counts отдельно для профилей. Записываются source hostname, совпавшее локальное правило, категория и время; URL path/query/headers не сохраняются. Источники Tor/Private заменяются общей меткой; Tor stop/profile delete и Reset очищают соответствующий журнал. History.clear не заменяет Reset tracker counters. Exact-host exceptions — явно сохранённая пользовательская конфигурация во всех профилях, включая Tor; маршрутизация/TLS/Kill Switch не отменяются. Полнота обнаружения трекеров/first-party/video рекламы не гарантируется.

Дополнение0.4.0: поисковые запросы Tor идут через выбранный Tor-профиль по отдельному настраиваемому шаблону (по умолчанию DDG HTML); подсказки по набору не отправляются. Блокировщик рекламы использует только локальные прозрачные правила без фоновых подписок. Карточки «ничего не найдено» показываются только по известному empty-result маркеру DDG либо404/410, не подменяют CAPTCHA/timeout.

Кнопка IP диагностики Direct/Private делает явный DNS lookup выбранного hostname через Chromium session. Отдельная кнопка network owner отправляет только public IP, затем ASN в RIPEstat (`https://stat.ripe.net/data/network-info/data.json`, `https://stat.ripe.net/data/as-overview/data.json`), с redirect:error/credentials:omit/timeout/ограничением ответа. Hostname/URL сервису не отправляются. Tor/Proxy/onion не делают эти DNS/provider запросы; серверный IP onion скрыт протоколом. Нет автоматических проверок при открытии сайта.

Локальные команды запускаются только после выбора папки и native подтверждения. История/вывод новой Console хранятся в памяти панели, ограничены, не отправляются в сеть и сбрасываются при смене проекта/закрытии. Copy явно записывает выбранный вывод в системный clipboard через проверенный IPC (до1MiB); чтения clipboard веб-страницам этот API не даёт. Сами явно одобренные команды работают с правами пользователя и могут выполнять сетевые действия вне browser transport policy.

RainCode не содержит рекламного идентификатора, аналитического SDK, отправки истории или автоматически включённого crash reporter. История и настройки локальные. Браузер не фильтрует сайты по политическим, культурным или тематическим категориям и не изменяет результаты выбранного поисковика. Это не означает отключение TLS, permissions или sandbox.

## Собственные сетевые действия

| Действие                                      | Получатель                                                  | Когда                                                            |
| --------------------------------------------- | ----------------------------------------------------------- | ---------------------------------------------------------------- |
| Сайт, redirects, favicon, подресурсы, workers | Адреса страницы                                             | При браузинге и по поведению сайта                               |
| Поиск                                         | Выбранный поисковик / пользовательский HTTPS-шаблон         | После Enter, не во время набора                                  |
| Проверка IP/proxy                             | `https://api.ipify.org?format=json` через выбранную session | Только явная проверка                                            |
| Proxy                                         | Настроенный пользователем сервер                            | Для запросов его профиля; локальные исключения могут идти прямо  |
| DNS / выбранный DoH                           | Системный/Chromium resolver или настроенный HTTPS endpoint  | При необходимости разрешения; DoH настройка общая для приложения |
| Поиск dev-серверов                            | Только loopback, фиксированный список dev-портов            | По явной команде                                                 |
| Включённый Tor                                | Tor relays/служебные узлы; назначение через Tor             | Только после включения пользователем                             |
| Подготовка Tor                                | `dist.torproject.org`, `openpgpkey.torproject.org`          | Команда разработчика `pnpm tor:prepare`; не обычный runtime      |
| Зависимости/упаковка                          | npm, Electron/build tool providers                          | При разработке и сборке                                          |
| Локальная пользовательская команда            | Определяется самой командой                                 | Только после системного подтверждения                            |

Нет фоновой погоды, внешних поисковых подсказок, новостей, синхронизации или автоматической проверки IP. Подсказки Omnibox читают только локальные закладки/историю. Onion-адреса не отправляются поисковику или Direct DNS. Стартовая сцена — локальный asset.

Это перечень инициируемых приложением действий и ожидаемых категорий Chromium, а не полный независимый сетевой аудит. Сайты, ОС, проверка сертификатов и Chromium могут иметь собственное сетевое поведение.

## Локальные данные

SQLite в userData содержит историю, закладки, настройки, метаданные загрузок, недавно закрытые вкладки и восстанавливаемую сессию. Сохраняются URL/title/index навигации без Chromium pageState с формами/паролями. Chromium хранит cookies/cache/storage в partitions профилей.

Direct и Proxy используют разные persistent sessions. Private и Tor — отдельные непостоянные sessions; их URL исключены из постоянной истории, восстановления, Recently Closed и сохраняемых метаданных загрузок. Скачанный пользователем файл остаётся на диске. ОС, backups, swap, дампы и сторонние программы могут сохранять следы.

Workspace ссылается на профиль: два пространства с одним profileId разделяют cookies и storage. Для разделения используйте разные профили. Закладки, заметки и snippets — общие явно сохраняемые данные, даже когда созданы из Private/Tor. Не помещайте туда секреты.

SQLite не зашифрована. Собственный менеджер паролей и хранение proxy credentials не реализованы. Экспорт настроек не включает cookies/историю/proxy passwords, но включает пользовательские search/DoH URL-шаблоны: секрет в таком URL сам по себе не будет надёжно распознан.

## Developer Workspace

Файлы доступны после явного выбора папки, с проверками пути и лимитами. Веб-страницы не получают к ним API. Выбор папки не означает согласия на выполнение её scripts.

Каждая команда и каждый snippet требуют отдельного системного подтверждения. Command runner работает с правами пользователя; заданная команда может читать файлы и обращаться в сеть. Секреты в коде, выводе, notes или snippets не скрываются автоматически. Вывод команд ограничен и показывается пользователю; это не изолированная среда выполнения недоверенного кода.

Встроенный список сети/HAR намеренно ограничен метаданными: query values, credentials и fragments удаляются, headers/cookies/bodies не записываются. Пути URL всё ещё могут содержать чувствительные значения; проверяйте HAR перед передачей. Штатный Chromium DevTools может содержать полные секреты текущего сайта.

## Режимы соединения

Direct раскрывает IP сайту. Proxy переносит доверие оператору, не обещает анонимность; TLS сайта продолжает проверяться.

Tor запускается явно и использует отдельную session через локальный SOCKS5. При вводе onion из обычного профиля требуется подтверждение, создаётся другая вкладка. Нет скрытого переключения Direct в Tor. При сбое нет прямого fallback. All-frame Tor preload удаляет WebRTC/WebTransport API, устройства/геолокация запрещены; эти меры не равны fingerprinting-защите официального Tor Browser.

Реально проверены bootstrap 100%, собственный v3 onion, отсутствие Node/IPC/WebRTC в основном документе/cross-origin iframe, запрос circuit, замена identity и остановка. Контролируемый SOCKS E2E покрывает hostname forwarding, storage и fail-closed. Полный DNS/IP/UDP packet capture пока не выполнен. Подробности: [TOR_MODE.md](TOR_MODE.md).

Штатное завершение очищает runtime Tor текущего запуска; crash и следы ОС не дают обещать гарантированное уничтожение данных.

## Управление хранением

Можно отключить/очистить историю, удалить данные сайта, удалить профиль и включить очистку Chromium storage/cache при выходе. Общая очистка при выходе не удаляет закладки, историю и скачанные файлы: ими управляйте отдельно. Политика third-party cookies, выборочная очистка категорий на выходе и полноценные контейнеры workspace остаются в [ROADMAP.md](ROADMAP.md).
