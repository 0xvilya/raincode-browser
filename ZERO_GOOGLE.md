# Zero Google: измеренная область и ограничения

Обновлено 24 октября 2026 года. Цель — исключить необязательные обращения **самого RainCode** к сервисам Google. Это не запрет Google Fonts, YouTube, reCAPTCHA или API, запрошенных пользователем/сайтом, и не скрытый blacklist контента.

## Что подтверждено по коду

В RainCode нет встроенного Google login/sync, рекламного SDK, удалённых поисковых подсказок, автоматической погоды или crash reporter. Стартовые assets локальные. Поиск выполняется после Enter по выбранному шаблону. DoH выбирает пользователь; оператор системного DNS не определяется по одному значению настройки браузера.

До Electron ready задаются `disable-quic`, `dns-prefetch-disable`, onion resolver rules и начальный `proxy-server=direct://`. Последний задаёт Direct для начальных/default/UI sessions до настройки отдельных профилей. Явные Proxy/Tor sessions затем конфигурируются собственным `session.setProxy`; их маршрутизация проверяется отдельно. Ни один switch не является доказательством «никаких Google-запросов никогда».

Sandbox, Site Isolation, TLS и permissions не отключаются ради уменьшения сетевого шума. Уменьшение фоновой активности не заменяет проверку сертификатов или предупреждения о загрузках.

`wpad` — имя локального автоматического обнаружения proxy configuration, **не Google**. В этом сопоставлении оно не повторилось после начального Direct. Это не универсальное утверждение о причинах всех DNS-запросов на любой ОС.

15-event report/raw до добавления marker сохраняются обновлённым скриптом в `artifacts/background-audit-history/*-previous-*.json` перед новым запуском. Это **post-fix, pre-marker** материал, не восстановленный исходный 177-event baseline. Каждый последующий запуск также архивирует предыдущий и текущий captures; точные пути находятся в поле `previousCaptures`.

## Воспроизводимый startup/idle аудит

Подготовьте зависимости и production assets, закройте другие тестовые процессы, затем выполните:

```powershell
pnpm build
node scripts/background-audit.mjs --seconds=30
```

Допустимая длительность — 10–120 секунд, по умолчанию 30. Скрипт:

1. Архивирует предыдущие отчёт/raw NetLog, создаёт новый временный userData и собственный HTTP fixture на `127.0.0.1` со случайным портом/путём.
2. Запускает настоящий Electron с `--log-net-log` **до загрузки приложения**, `capture-mode=Default` и лимитом 10 MB. Проверяет, что Tor не стартовал.
3. Наблюдает чистую стартовую страницу заданное время без сайтов, поиска и Tor.
4. **Только после idle** открывает собственный loopback marker в обычном RainCode WebContents. Никакие неизвестные сайты для positive control не нужны.
5. Требует одновременно реальное получение marker сервером, `URL_REQUEST_START_JOB` его URL, TCP endpoint marker и доступную временную границу NetLog. Если контроль не найден, записывает диагностику и завершается ошибкой.
6. Закрывает Electron/сервер, удаляет только собственный проверенный временный каталог и разбирает законченный NetLog.

Отчёт содержит версию приложения/Electron/Chromium, OS release, архитектуру, startup switches и SHA-256 `dist-electron/main.cjs`. Эти поля позволяют привязать результат к проверенному snapshot, а не ко всем будущим сборкам с тем же номером версии. Указываются фактическая длительность idle и время запроса контроля.

## Чтение отчёта

- `controlledMarkerObserved` подтверждает, что логирование/парсер действительно видят известные URL/TCP события, а не возвращают пустые списки из-за неверного event mapping.
- `positiveControl.*` разделяет серверное, URL и TCP подтверждения. Marker — ожидаемое **локальное** соединение, не скрытая внешняя активность.
- `idleExternal*` — события до первого marker URL; `external*` — startup/idle/control в целом. Имя «external» означает «не распознано как loopback», а не доказанную принадлежность публичной сети или определённой компании.
- `knownGoogleHostsObserved` — совпадения URL/DNS с опубликованным в отчёте ограниченным списком доменов. Этот список — classifier аудита, не runtime blacklist сайтов.
- `noExternalTrafficObserved: true` относится только к разобранным URL/DNS/TCP событиям данного capture. Сам по себе успешный exit скрипта не означает полный Zero Google аудит: проверяйте и positive control, и содержимое списков.
- Raw NetLog и архивы находятся в `artifacts`, исключённых из Git. Даже Default metadata может содержать чувствительные URL; не используйте личный профиль и не публикуйте raw без проверки.

Корректная формулировка результата: «В указанном Windows snapshot и интервале startup/idle необязательные обращения из охваченных категорий Chromium не обнаружены; положительный локальный контроль был виден». Абсолютное «никаких обращений никогда» этим не подтверждается.

## Что не охвачено

Это **не OS packet capture**. Node fetch/sockets, Tor daemon, пользовательские дочерние команды, проверка сертификатов ОС, UDP и неизвестная принадлежность IP не аттестованы. Google-связь нельзя надёжно установить или исключить только по IP без attribution. Нужны отдельные проверки DoH, IPv6, workers, service workers, WebSocket, длительного browsing, всех профилей и всех ОС.

Следующие этапы: сопоставление process-level captures, idle/internal/controlled HTTPS/search/Proxy/Tor интервалы, отказ proxy, Network Kill Switch и уже открытые соединения. У Kill Switch собственная задокументированная граница; не приписывайте ему контроль других программ ОС.

Встроенная Dev Panel/HAR ограничена метаданными вкладок и не заменяет startup NetLog. Собственные соединения описаны в [PRIVACY.md](PRIVACY.md), фактические проверки — в [TEST_REPORT.md](TEST_REPORT.md), работа по этапам — в [PROGRESS.md](PROGRESS.md). Документация механизма: [Electron NetLog](https://www.electronjs.org/docs/latest/api/net-log), [поддерживаемые switches](https://www.electronjs.org/docs/latest/api/command-line-switches).

## Проверенный захват 24 октября 2026

`artifacts/background-audit.json`:30s idle,232events, положительный localhost control подтверждён HTTPserver/URL_REQUEST_START_JOB/TCP; внешние request/resolver/TCP и knownGoogle hosts в этой выборке отсутствуют. Исходный снимок main указан SHA256 внутри отчёта. Скрипт ранее неверно завершал async waitForFunction до загрузки control; теперь он опрашивает фактическое состояние до завершения и требует реальный serverhit. Это ограниченный ChromiumNetLog audit, не обещание абсолютного Zero Google для ОС/Node/Tor/всех сайтов.
